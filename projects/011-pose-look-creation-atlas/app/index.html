固定同一个人、姿势、机位、背景和灯光，只换婚纱。这样比较的主要差异才是款式，而不是整个画面的变化。

先确认人物与服装，再换姿势、场景和氛围。每轮知道自己改了什么，比把所有要求一次塞进提示词更容易判断。

WHAT EACH LAYER DOES

同样叫“姿势”，交付物不一样。

素材

姿势 / 服装图库

交付静态图片。帮助表达目标，减少寻找和描述的时间。

可作为参考，不会自己执行生成。
编辑

3D 摆姿 / 机位编辑器

交付自己设计的姿势、构图或控制图。部分工具支持模型与动画文件。

导出哪些内容，要逐个工具确认。
生成

图像 / 视频模型

交付新画面或新视频。保真度、稳定性和成本需要实际评测。

生成画面不等于拿到真实三维资产。
资产

3D 重建 / 动作 / 绑定

交付网格、骨架、蒙皮或运动参数，进入另一套制作流程。

还要处理适配、形变与软件兼容。

FROM LINKS TO AN UNDERSTANDING

这次探索，留下了什么判断？

  1. 起点

    两条分享并不是两个已发布的开源图库。

    第一条转述日文姿势库；中文 GitHub 镜像主要增加翻译和检索。第二条是服装库制作预告与多参考生图演示，完整资源入口尚未确认。

  2. 厘清

    免费参考、代码开源与素材商用，是三件事。

    原站允许符合条款的作品创作，但禁止原图再分发。镜像 MIT 不覆盖图片；原站还有真人与未成年人用途限制。真人婚纱方案应另用自有或适当授权的参考。

  3. 扩展

    视频和真实 3D 有价值，但不是图库附带的能力。

    角色跟随视频、视频恢复人体动作、图片生成网格和自动绑定，分别需要不同模型。它们不是“下载姿势图”自然就能得到的结果。

  4. 聚焦

    先把婚纱选款与个人造型做成能比较的创作流程。

    对我们的价值假设是：减少找图与反复描述，让选款沟通更具体，成功方案可继续修改。是否值得做产品，要用真实需求、保真效果和返修成本验证。

下一步最值得验证

用自己有权使用的人物图和三套真实服装，做一轮同条件换装比较。记录身份保持、款式细节、成功率、返修次数、耗时和单次成本；先确认有用，再考虑更大的平台。

看不懂文件名？先看它交付的是什么。
PNG / 控制图
PNG 是图片。OpenPose 表达关节点，深度图表达远近，法线图表达表面朝向，Canny 表达边线；它们帮助模型控制画面。
姿势 JSON
保存工具自己的关节数值或场景参数，往往需要用原工具重新打开。
GLB / FBX
三维文件容器，可以装网格、材质、骨架、动画等；实际装了哪些内容，取决于工具与导出设置。
VRM / VRMA / 蒙皮
VRM 常用于人形角色，VRMA 保存人形动作。蒙皮是让模型表面跟随骨架运动的权重分配；格式支持不等于已经完成角色适配。

03 / CREATIVE DIRECTIONS

每个方向都写清输入、固定项、变化项与交付。
这里的价值是待验证的产品假设，不能当效果承诺。

可扩展的产品目标

先有稳定结果，再有产品。

  1. 01 · 个人创作工作台

    参考、指令、结果和返修关联保存。

  2. 02 · 可比较的选款方案

    同条件对比，记录喜欢与不喜欢。

  3. 03 · 店铺沟通与款式册

    关联真实商品，人工确认商品细节。

现成图像工具已经能尝试多参考换装。新产品需要证明：比直接在通用工具里生图，选款更快、商品更准、方案更好复用。只是把图库与提示词放到一起，投入价值有限。

本项目已完成独立生图小样本与研究方案整理，尚未接入实时生成、商品系统或客户照片服务。
