# 第一步：定义研究回查能力

日期：2026-10-28。依据：用户已选择“跨项目检索、查看出处、保存判断”，并要求创建真正可用的 Skill，同时把每一步同步到网页。

## 这项能力做什么

输入库名、仓库链接、能力词或关于已有研究的提问，在授权的研究总库中找到相关记录，读取依据，区分原文、推断和未确认项；用户要求保存时，另存可复核的判断记录。

## 为什么先写约定

“研究一下”可能指重新联网调研，也可能指找回已有结论，两者使用不同资料与验证方式。本轮先让已有研究回查稳定可用。成功与失败有明确含义，后续才知道该写什么规则、补什么工具。

| 设计项 | 本轮约定 | 原因与验证 |
| --- | --- | --- |
| 输入 | 查询词或 GitHub 仓库链接，明确的研究总库根目录；可指定项目 | 不猜私人目录；检查根登记格式 |
| 来源 | 登记项目 README 与 research Markdown；排除上游快照和本轮生成记录 | 比网页旧工具只读 README 更深入；不把自动生成证据又当成新研究 |
| 结果 | 项目、原文片段、行号、来源哈希、检索范围、警告 | 方便人和程序追溯；不只返回模型总结 |
| 对象身份 | 仓库链接按完整 owner/repo 核对 | 已有相似前缀误命中案例；单独回归测试 |
| 无结果 | “本次范围未找到”，交代实际扫描范围 | 缺失证据不能推出从未研究过 |
| 判断 | 原文事实与本次推断分开；登记状态不等于实测状态 | 人或独立执行者逐条核对结论 |
| 保存 | 用户要求时另存新文件；验证后写入，拒绝覆盖 | 已有资料、浏览器笔记和私人库保持原样 |
| 来源变化 | 旧证据校验失败时阻止保存，重新检索取证 | 以真实修改的隔离样本验证，不能修改哈希绕过 |
| 范围限制 | 本地关键词检索；无联网、语义向量、PDF、私人日记或聊天接入 | 可执行和可验证的首版；后续扩展需各自适配 |

## 什么时候算可用

1. 能通过库名或完整仓库链接找回真实项目，引用可定位。
2. 能读到 README 外的研究说明，并准确说明资料范围。
3. 没有匹配、资料缺失和来源失效都有明确反馈。
4. 保存成功能读回；失败或路径冲突不覆盖旧文件。
5. 新执行者只拿 Skill 和必要上下文就能完成真实回查。
6. 技能包结构有效，安装副本与研究源包一致，给出可复用调用方式。

## 你在这一步要学会什么

先用自己的话回答五个问题：什么时候用、读哪里、返回什么、最不能犯什么错、怎样算完成。这里已经从用户已有需求给出首版答案；它是下一步的设计依据，不是一次完整验收结果。
