# 实施与学习计划：研究回顾入口

日期：2026-10-28。规格见 [SPEC.md](SPEC.md)，共同底线见 [CONSTRAINTS.md](CONSTRAINTS.md)。本文件记录任务、依赖和验证方式；实际完成项、发现和结果由 [verification.md](verification.md) 统一记录，避免把计划勾选当作证据。

## 工作方式

每个阶段都回答七件事：**触发条件 → 必要输入 → 操作步骤 → 可检查产物 → 通过标准 → 失败分支 → 交给下一步。**

这些是本次从源码整理的学习框架，不是上游统一规定的字段。25 项技能的“本轮采用”表示相关方法进入实际工作；不等于完整执行上游所有步骤，也不等于效果验证通过。

## 决策与理由

| 决策 | 理由 | 取舍 |
| --- | --- | --- |
| 使用真实总库登记和 README | 回答近期真实查找需求，有现成可核对依据 | 只覆盖当前登记快照，不能代表全部聊天历史 |
| 浏览器静态检索 | 10 项资料规模小，易解释、可本地运行 | 字面查询不解决语义理解或生成回答 |
| 单独保存来源快照与哈希 | 查询结果能回到构建时的依据 | 源文件更新后需重建索引 |
| 笔记本地保存并手动导入导出 | 支撑个人回顾，不引入账号和服务 | 用户需保管导出文件，不能跨设备自动同步 |
| 导入冲突明确拒绝 | 避免无声覆盖已有理解 | 需要用户自行核对后选择保留内容 |
| 真实过程放回 010 网页 | 操作、原理、产物和证据集中回看 | 教学过程需持续与实测结果校准 |

## 任务与依赖

### T1：固定输入与查询契约

输入：已有项目登记、研究说明、用户本聊天目标。动作：只读调查，明确范围，保存规格和质量底线。

产物：SPEC、CONSTRAINTS、本计划及页面学习数据。验收：每个用户动作有对应验收条件；未命中和研究状态的语义准确。失败分支：若来源与用户目标不一致，调整范围并记录原因后再实施。交接：T2、T3。

### T2：完成真实查询与出处闭环

输入：T1 契约和允许列表。动作：构建带哈希与段落行号的快照；实现查询规范化、AND 关键词和阶段筛选；界面显示并查看来源。

文件职责：`scripts/build-recall.mjs`、`app/recall-data.js`、`app/recall-core.js`、来源清单及页面。

验收：A1、A2、A3；真实查询能回到对应项目和片段，空状态不补造结论。

验证：

```powershell
node scripts/build-recall.mjs
node scripts/build-recall.mjs --check
node --test tests/recall.test.mjs
```

失败分支：保留查询输入、预期和实际结果，定位构建、匹配或显示环节，修复后重验相同案例。交接：T3、T4。

### T3：完成回顾笔记保存与恢复

输入：T1 笔记契约和当前项目集合；依赖 T2 的项目编号。动作：实现严格格式验证、本地保存、导出与粘贴导入合并；界面提供成功、冲突和失败反馈。

验收：A4、A5。重点是已有笔记保持：非法版本、未知项目、重复条目、超长文本、冲突和存储异常均不破坏原保存状态。

验证：纯函数/存储测试，加实际浏览器保存、重新加载、导出与粘贴导入。模拟存储异常与浏览器自然行为分开记录。

失败分支：先保留旧状态和错误，不清空存储；定位校验、合并、写入或提示环节，修复后核对失败前后状态。

### T4：将工程过程接回学习导览

输入：T1 文档，T2/T3 实现与实际证据。动作：提供六阶段路线、Skill 关联、产物链接、回顾问题、25 项覆盖表和清楚状态。

验收：A6；每项技能唯一、来源有效，实际动作、待验证与未触发能区分。现有 25 项目录和旧实验继续保留。

验证：数据结构与覆盖核对，浏览器导航、键盘和窄屏检查。失败分支：修复入口或措辞，不通过改写测试结果弥补页面陈述。

### T5：独立审查、故障记录与本地交付

输入：实现、规格和验证记录。动作：审查真实使用闭环及数据保持；记录发生过的缺陷与修复；核对变更范围、重复检查入口和本地服务。

验收：A1–A6 的实际结果均已登记，未执行项明确保留。运行仓库根目录 `npm.cmd run check`；核对已有导览功能无明显回归。浏览器截图和验证记录放在本子项目。

失败分支：按原因回到 T2/T3/T4；不通过降低约束宣布完成。交接：用户实际回顾和后续反馈。本轮无提交、推送、线上部署或真实格式迁移。

## 并行分工与检查点

- 独立内容作者：规格、约束、计划、六阶段教学数据。
- 核心实现者：来源快照、查询与笔记契约、行为测试。
- 页面集成者：学习入口、查询界面、笔记交互及浏览器验收。
- 并行前共享字段契约；只修改各自分配文件。接口变化及时同步，不隐式猜测。
- 检查点 1：规格和核心契约一致，再连接页面。
- 检查点 2：核心测试与真实使用路径都覆盖，再填写验证结论。
- 检查点 3：所有正文、覆盖状态和证据相符，再交付页面入口。

## 25 项能力的观察边界

- 需求访谈采用已有上下文与偏好确认，不虚构完整问答。
- 测试驱动需要保存真实失败到通过；没有证据时保持待验证。
- 调试应有真实实现缺陷的复现与修复；正常拒绝非法输入属于边界验证。
- 独立质疑和代码审查需要实际复核记录。
- 自动检查在本地运行，不等于已接 CI；工作区核对不等于已提交。
- 性能测量与性能优化分别记录；没有前后比较，不写优化收益。
- 未知笔记版本被拒绝不算迁移演练；未来格式升级另立规格。
- 交付是本地入口与可复查记录，不能写成线上发布或生产监控完成。
