# 资料理解与检索研究笔记

> 状态：2026-10-28 基于公开主页、文档和论文的桌面研究。上游默认分支会变化，本次未固定 commit；没有安装、运行或对项目做性能与效果实测。案例均为人工编写的虚构示意。

## 从产品比较到核心问题

DeepTutor 是可自部署的学习工作台，将知识库、问答、练习、阅读和学习记忆接到模型与工具；其效果依赖模型、解析、检索及工作流。NotebookLM（Google 已更名为 Gemini Notebook）提供托管的资料问答、引用和多种学习内容生成；它不是开源项目，本研究把它作为使用体验对照。两者有大量能力重叠，公开材料不足以证明某一个在用户资料上普遍更好。自部署也不自动意味着模型推理全部在本机。参见 [DeepTutor](https://github.com/HKUDS/DeepTutor) 与 [Google 更名说明](https://blog.google/innovation-and-ai/products/gemini-notebook/notebooklm-gemini-notebook/)。

真正值得继续研究的是：资料能否被完整读出，结构、上下文和时间能否保留，相关证据能否被找回，答案能否被原文支持。上层的题目、音频、图表或课程界面是围绕这些能力的产品流程，并不能自动修复底层错误。

## 层次和数据流

```text
原始资料：PDF / 图片 / 文档 / 笔记 / 音视频
  → 解析：文字、表格、公式、章节、位置
  → 组织：原文、片段、索引、来源与时间
  → 获取：直接读取、关键词、向量、章节树或关系查询
  → 模型与流程：回答、综合、生成题目、校验
  → 呈现：引用、阅读、练习、报告或音频
```

这是一张概念图，不是所有系统都必须采用的固定管线。短文可以直接交给支持相应输入的模型处理；较大资料集可能使用索引。索引并不等于对大模型重新训练。向量数据库负责保存和检索数据，不自动完成 OCR、事实判断或时间推理。

## 项目对比：同一链路中的不同角色

| 项目 / 层次 | 主要机制与研究价值 | 限制和代价 |
| --- | --- | --- |
| [MinerU](https://github.com/opendatalab/MinerU) / 解析 | 用版面识别、OCR 等处理复杂文档，并输出文字、表格、公式和结构；适合研究 PDF 怎样变成机器可读数据。 | 扫描、手写、复杂表格仍可能误识别；不同解析引擎的耗时、依赖和模型要求不同。 |
| [Docling](https://github.com/docling-project/docling) / 解析 | 将版面分析、OCR 和表格结构识别等阶段组织为结构化文档；适合研究阅读顺序和来源位置。 | 分阶段输出不保证都正确；语言、文件和模型的表现需同样本核验。 |
| [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) / 解析 | OCR 与文档结构识别工具；可研究文字与表格的定位。 | 解析不自动解决检索或推理；适配、模型和识别质量需要评估。 |
| [olmOCR](https://github.com/allenai/olmocr) / 解析 | 采用视觉语言模型理解页面，输出按阅读顺序组织的文本；可研究复杂版面与训练数据准备。 | 视觉模型可能漏字或生成无依据内容；本地推理对计算资源要求较高，不保证对中文或手写材料最优。 |
| [BGE-M3](https://huggingface.co/BAAI/bge-m3) / 检索模型 | 多语言稠密、稀疏及多向量表示，可比较不同说法的相关性。 | 相似度不是事实真伪或时间理解；它不是数据库，中文表现需用实际问题验证。 |
| [ColBERT](https://github.com/stanford-futuredata/ColBERT) / 检索算法 | 保留词元级向量，用 MaxSim 等后期交互进行更细的匹配。 | 多向量带来索引和计算开销；不是完整产品，不保证所有语料均优于单向量。 |
| [Qdrant](https://github.com/qdrant/qdrant) / 搜索引擎 | 存储和查询向量及附加信息，可结合语义、稀疏检索和条件过滤。 | 数据库本身不是文档解析器或事实判断系统；向量需由模型生成或配置推理，索引和服务需要维护。 |
| [OpenSearch](https://github.com/opensearch-project/OpenSearch) / 搜索引擎 | 将关键词检索与向量检索结合，并支持过滤和排序；可研究人名、日期等精确检索与语义查找的取舍。 | 需要建立索引并维护服务；中文分词、混合权重和向量模型会影响结果。 |
| [PageIndex](https://github.com/VectifyAI/PageIndex) / 文档结构检索 | 利用文档的章节树和模型推理定位相关内容；不必使用向量数据库。 | 依赖结构和模型判断，可能增加延迟与调用；官方区分本地文字型 PDF 与云端 OCR/图片理解能力。 |
| [Graphiti](https://github.com/getzep/graphiti) / 时间与关系 | 用事件原文、实体、关系及有效时间组织持续变化的信息，支持追溯来源与混合检索。 | 抽取、去重和矛盾判断可能出错；事件时间与入库时间要区分，不能让图谱替代原文。 |
| [Microsoft GraphRAG](https://github.com/microsoft/graphrag) / 全局关系 | 从文本抽取实体关系，形成社区摘要，综合回答跨资料的整体主题；DeepTutor 可将其作为一种引擎。 | 建图和全局查询可能耗时且有模型费用，抽错会传递；官方说明仓库主要处于维护模式。 |
| [RAGFlow](https://github.com/infiniflow/ragflow) / 完整知识库平台 | 整合解析和检索，DeepDoc 涉及 OCR、版面、表格识别，适合看完整处理链路。 | 仍需模型、解析和检索配置；平台复杂度不代表资料准确，也不代表比 NotebookLM 更好。 |
| [OATutor](https://github.com/CAHLR/OATutor) / 自适应教学 | 使用贝叶斯知识追踪，根据作答记录估计知识点掌握概率并选择练习。 | 依赖结构化课程、题目和技能；概率估计不等于证明理解，也不能直接处理任意资料。 |
| [pyKT](https://github.com/pykt-team/pykt-toolkit) / 教学研究 | 提供知识追踪模型与评估研究，关注根据历史学习行为预测后续表现。 | 是研究工具，不是完整资料问答产品；预测成绩不能直接等同于真实教学成效。 |
| [pyBKT](https://github.com/CAHLR/pyBKT) / 教学算法 | 实现贝叶斯知识追踪及扩展，用答题行为估计技能掌握状态，可用于理解猜对、失误和学习概率。 | 需要可用的作答历史与合理参数；估计概率不证明学习者真正掌握。 |
| [Tutor MCP](https://github.com/ArnaudGuiovanna/tutor-mcp) / 教学工具服务 | 将知识追踪、复习安排和先修关系等教学逻辑作为工具提供给模型；可研究生成与教学状态的分工。 | 依赖模型出题、评分及输入数据；教学效果、参数和长期表现仍需独立验证，不是完整独立学习应用。 |
| [STORM](https://github.com/stanford-oval/storm) / 研究流程 | 从多个视角提问、搜索资料、整理大纲和带引用的长文。 | 仍依赖模型与来源，流程增加耗时和调用；引用不能保证结论正确。 |
| [OpenResearcher](https://github.com/TIGER-AI-Lab/OpenResearcher) / 研究训练 | 研究合成长程研究轨迹、基于轨迹训练及评测；可观察多轮查找能力怎样成为训练目标。 | 是训练研究项目而非现成资料问答应用；复现需要较多算力，代码、数据与权重许可需分别核验。 |
| [Ragas](https://github.com/vibrantlabsai/ragas) / 评估 | 提供检索上下文召回、回答忠实度等评估方法；可研究如何检查结果与证据的关系。 | 自动评分可能误判；忠实于检索内容不证明资料本身真实，应结合人工核验。 |

这些项目并非全部互为替代：例如 MinerU 是解析器、BGE-M3 是模型、Qdrant 是数据库；一个实际系统可以组合它们，也可以只选其中一部分。

表中 19 个开源项目或模型处在不同层次；DeepTutor 是研究起点，NotebookLM 是托管产品对照，不计入这 19 项。项目链接与许可随上游变化，具体效果、资源需求和适用性尚未实测。

| STORM、OpenResearcher、Ragas | 比较研究流程、多轮轨迹训练和评测：一个组织研究、一个研究训练、一个评估，不互为替代。 | 多轮调用或自动评分必然使结论可靠。 |

## 深入分析：每一层可能丢失什么

### 解析与结构

扫描件可能漏字，双栏阅读顺序可能颠倒，表格可能丢失行列关系，公式和图片可能无法完整提取。原文页码、页面坐标和标题层级有助于核对，但即便保存了位置，也不保证提取内容正确。复杂资料应核对文字、顺序、表格、公式和缺失区域。

### 搜索与表示

关键词搜索擅长匹配确切人名、术语和数字，但不一定识别不同表述；向量检索能找语义相近的内容，但相似不一定能回答问题。二者可以结合，配合日期、来源过滤和重排序。中文关键词基线应记录分词方式；不能假设任一默认全文索引都适合中文。

PageIndex 按章节树寻找内容，与关键词和向量是不同思路。GraphRAG 和 Graphiti 则尝试增加实体、关系或全局结构；关系通常仍需模型抽取，不能把图上的边直接视为事实。资料少时，直接输入全文也可能是更简单的基线。

### 模型理解与时间

模型可能把推测写成事实、混淆人物、忽略否定，或把过去状态误认成现在状态。示意：3 月“项目暂停”、5 月“项目恢复”，不能推导出 5 月仍暂停。历史回填时应分别记录事件实际时间和入库时间。引用证明系统指向某个来源，并不能证明资料或模型结论本身真实。

原始资料、可重建索引与 AI 生成物应明确区分。索引版本化有助于重建过程保留旧索引，但不能替代原文、编辑缓存及备份的保护。

## 后续演示规划

**以下均为待实施计划，没有实测结果。** 先采用人工编写的虚构材料，明确运行环境、模型来源、是否联网和费用；不接入正式日记、未保存编辑缓存或其他私人资料。

### 1. MinerU：文档解析

- 构造一份小型虚构 PDF，包含标题、双栏或分页正文、表格，以及有明确页码的文字；有条件时再提供对应扫描图。
- 保留一份人工核对的文字和表格结构作为参照，分别检查漏字、阅读顺序、表格行列、公式及原文定位。
- 比较原始页面与解析结果，记录引擎配置、处理时间和错误；不把 README 的宣传示例当成自己的测试结果。

### 2. BGE-M3：中文检索

- 准备若干虚构片段、问题和人工标注的正确来源；包含同义说法、精确日期/人名、否定句和没有答案的问题。
- 与关键词基线比较召回片段，记录中文分词、切分方式和模型版本；如未来使用向量数据库，明确其与模型的职责不同。
- 检查结果排序、来源和未找到依据时的行为；不预先虚构相似度分数或成功率。

### 3. Graphiti：事件与时间

虚构样本：

```text
2026-03-01：项目 A 因接口问题暂停。
2026-05-01：接口问题解决，项目 A 恢复推进。
```

- 在明确事件发生时间和入库时间后，检查抽取的实体、关系、有效时间和原文来源。
- 分别提出“3 月状态是什么”“5 月之后是否仍暂停”等问题，并准备没有证据的问题；人工核对生成事实与原始记录。
- 记录抽取错误、矛盾判定、模型调用和成本；生成关系只能作为待核验结果。

### 共同评估

对同一组标注样本记录：解析完整性、相关原文是否召回、引用是否指向正确来源、时间顺序、没有依据时是否明确说明、耗时及成本。先人工核验；自动评分可以辅助，但不能单独证明资料真实或答案可靠。只在实际运行后报告数值，注明数据、模型、版本和条件。

### 后续扩展对照：条件具备后再决定

1. **解析对照**：对同一份虚构文字 PDF 和扫描件，分别测试 MinerU 与 Docling；必要时补充 PaddleOCR、olmOCR。输出页面、文字、表格和标注来源，对照人工标注检查漏字、阅读顺序及位置，记录模型、设备、时间与许可证。
2. **检索对照**：以相同片段和中文问题比较关键词基线与 BGE-M3；若需要进一步研究，再加入 ColBERT 或 PageIndex。Qdrant、OpenSearch 分别作为可选搜索基础设施，检查不同条件下的结果与成本，不能把模型和数据库直接当作同类竞品。
3. **关系对照**：比较直接查原文、Graphiti 时序关系和 GraphRAG 的整体主题。检查事件时间、原文证据、相互矛盾的记录和未包含答案的问题，不让图谱替代原文。
4. **学习与研究扩展**：用虚构作答序列查看 pyBKT 的状态变化，结合 OATutor、pyKT 与 Tutor MCP 阅读教学流程；研究 STORM 的问题和证据组织，并仅在资源条件合适时研究 OpenResearcher 的训练流程。不能把虚构演示写成真实教学效果。
5. **评估**：可用 Ragas 辅助检查召回与回答忠实度，但最终以人工核对来源、时间和结论为准；始终记录环境、是否联网、授权条件、费用及失败案例。

当前阶段只维护规划与资料，以上对照全部未运行。未来测试先明确范围与隔离环境，使用虚构材料，不接入 ReflectFlow 正式库、应用数据、未保存编辑缓存和备份。

## 完整沟通补全：研究缘起、结论层次与能力扩展

本研究最初要回答的是“DeepTutor 有什么能力，是否值得安装”。在与 NotebookLM 的资料问答、练习和展示对照后，关注点转为建库时间与配置、维护成本是否换来实际新增收益。项目热度说明受到关注；公开使用反馈能说明有人尝试，但不能换算活跃人数、留存或教学收益。算法创新、系统工程可靠性、日常使用价值分别评价。

“没有独立大模型”不等于“没有技术深度”。结构化解析、细粒度检索、时间一致性和教学状态建模都需要工程或算法；大模型、解析和召回相互制约。更复杂的方案也不必然优于直接阅读、全文搜索或日期筛选。

### 补足讨论中的5项延伸工具

| 对象 | 机制 | 研究价值与边界 |
| --- | --- | --- |
| [LlamaIndex](https://github.com/run-llama/llama_index) | 资料连接、切分、索引、检索与模型编排框架。 | 查看各模块如何组合/替换；并不自动保证文档处理或检索正确，云服务能力与开源组件分开核对。 |
| [LightRAG](https://github.com/HKUDS/LightRAG) | 模型抽取实体关系并结合图和向量等检索。 | 对照普通片段查询是否更容易找到关系；仍依赖抽取、配置与建库成本，不等同于时序事实管理。 |

因此完整清单为19个重点项目/模型、DeepTutor与NotebookLM两种应用对照，以及5项延伸工具，共26个关联对象。并非26个同类库，也不需要全部安装。

### 如何解释“理解资料”

- 解析输出文字、结构与位置，不能证明读懂论点。
- Embedding 输出检索表示，不能直接还原成完整、可信的事实库。
- 数据库保存和检索表示；领域意义由输入、模型与程序定义。
- 图谱把提取结果组织为实体关系；推断、实体合并和时间失效都可能错。
- 教学模型估计技能掌握；它不等同于资料问答或真实理解。
- 生成模块根据可见证据组织答案；引用存在不是正确性证明。

### 对我们的六类可扩展能力

1. 论文与教材助手：保留表格、章节和页码，检索与解释后能回到原页。
2. 跨日记录回顾：找到前后原话，区分当时观点与当前状态，明确事件时间与导入时间。
3. 主题与阻碍归纳：比较直接归纳和图检索是否有额外收益，避免把相关性写成因果。
4. 工作资产沉淀：找出历史成功案例，人工核验适用条件，再形成知识卡、步骤或提示词。
5. 自适应复习：将技能映射、作答记录、掌握估计与讲解分开，进一步验证评分可靠性。
6. 多视角专题研究：组织问题、原始证据和反例，核查引用，保留不同观点及未知部分。

这些都是候选扩展，没有接入正式日记或现有重要库。它们不表示当前页面已有可执行能力。

### 最小实验及继续投入条件

先用人工标注的虚构或公开样本：解析实验看漏字、阅读顺序、表格和页码；检索实验看正确来源是否进入前k个结果（Recall@k）及顺序（如MRR），同时保留模型、切分、分词、时间和成本；时间实验加入乱序导入、同名人物、否定、状态改变和缺乏答案的提问。先评检索，再评最终回答。

对照始终包括直接阅读或合适的中文关键词基线。重排序不能补回完全没召回的依据，图谱不能替代原始记录。只有当某层在相同样本与任务上显示出可核验收益，才继续引入更复杂模型、服务或关系结构。Ragas等自动评估必须与人工来源检查对照；教学或研究训练阶段按资源与需求决定。
