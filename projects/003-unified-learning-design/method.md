# 内容 视觉 讲解与交互统一设计方法

[项目入口](README.md) · [填写模板](templates/topic-brief.md) · [应用示例](examples.md) · [验收清单](review-checklist.md)

先确定主题与合适的载体，再让相互关联的章节持续展开。每一页保留熟悉的线索、增加新的发现，视觉、讲解与交互沿同一主题发展。完成后的体验应当让用户感到探索过程连贯，并能带走对主题的理解。

## 先建立连续的主题路径

写出五件事：主题是什么、用什么载体进入、哪个对象贯穿、章节怎样接续、风格规则如何保持。可以从一本主题书开始，也可以选择档案册、工作台、标本册等适合内容的载体。

在[书页关联图](experience-map.md)中，每章都填写“从前面保留什么、这一章增加什么、带到下一章什么”。当页与页之间已经接上，再用下面的步骤完善讲解与交互。一个主题、一个载体、关联章节、持续风格与逐章发现，共同构成体验的主线。

## 一 明确用户最后能做什么

先写一个可以检验的目标：**体验结束后，谁能在什么情境下，解释、判断或完成什么。**

“介绍节奏”范围太大。可以先做“让没有乐理基础的人听出两段相同拍数的节奏有什么不同，并摆出一个自己的节奏”。“介绍编程”可以收窄为“看懂筛选条件如何决定哪些数据留下”。

随后记录用户常见的一个误解，并设计一道换了材料的检验题。检验题要能区分理解和照着界面模仿。例如筛选演示用了年龄，新题可以改为商品库存，判断规则保持一致。

产出三句话：目标、常见误解、检验方式。后续增加的场景都要服务于它们。

## 二 拆出内容中真正需要看懂的关系

把主题拆成几个相互依赖的问题，再为每个问题找出对象、条件、变化和结果。

| 内容关系 | 适合优先尝试的表现方式 | 可以安排的操作 |
| --- | --- | --- |
| 部分和整体 | 分层、剖面、组合图 | 拆开、组合、显示一层 |
| 条件和结果 | 同一对象的前后状态 | 改一个条件、比较两种结果 |
| 顺序和过程 | 时间线、步骤、流向 | 逐步推进、回放、交换顺序 |
| 分类和规则 | 卡片、集合、边界 | 分类、改规则、查看判断 |
| 数量和比例 | 长度、面积、刻度 | 调数值、比较比例 |
| 观点和证据 | 证据卡、来源、对照 | 查看来源、并列比较、调整判断 |
| 感受和表达 | 图像、声音、文字的并置 | 选择、重组、比较自己的感受 |

这些是起点。内容如果依靠空间结构理解，可以尝试 3D；规则比较常常用二维卡片更清楚。选择表现形式时，说明它究竟帮助用户看懂了哪一层关系。

章节按理解依赖排列。例如先认识“条件判断”，再介绍“多个条件组合”。每个场景先承担一个主要概念，其他信息按需展开。

## 三 为主题选择一个统一的体验环境

为整个主题写一句环境描述，例如“在一张音乐工作台上编排节奏”“在档案桌上对照几份记录”。这个环境要能自然容纳内容对象、用户动作和反馈。

用三个问题检查环境：对象放在这里是否容易理解，用户在这里会做的动作是否符合主题，不同章节能否在这个环境里自然衔接。若一个比喻反而增加解释负担，直接使用清晰的图表和控件。

统一环境可以带来以下连续性：同一件物品在讲解、操作和结果中始终可辨认；新增章节像继续探索同一个主题；字体、材质和动效共同支持内容语气。

环境比喻需要标明边界。例如“数据流水线”能表示处理顺序，但展示时也应说明原数据是否保留、当前看到的是原数据还是处理结果。

## 四 约定一套表达规则

在画页面前先确定下表，后续场景沿用它。

| 规则 | 需要约定的内容 | 示例 |
| --- | --- | --- |
| 对象身份 | 同一个概念如何始终被认出 | 固定名称、形状和编号 |
| 颜色含义 | 颜色在各场景中承担什么意义 | 选中、预测、实际结果各有固定含义 |
| 图形含义 | 大小、位置、粗细分别代表什么 | 时间轴的位置代表先后，线宽代表数量 |
| 动作含义 | 点击、拖动、展开会发生什么 | 拖动卡片表示重新排序，展开卡片表示查看细节 |
| 动效含义 | 哪种变化需要用运动说明 | 对象移动显示去向，转场表示进入下一阶段 |
| 文本分工 | 标题、正文、提示、注释各说什么 | 标题提问题，正文解释，提示说明如何操作 |
| 感官替代 | 声音、颜色、运动如何补充说明 | 声音配节拍指示，颜色配文字状态 |

颜色不要单独承担状态表达。文字、声音、图示之间需要说同一件事。动效时长和装饰可以调整，代表知识关系的规则应保持稳定。

## 五 把每个场景写成一次完整的理解过程

一个场景建议包含以下环节。根据内容需要合并环节，保持问题、操作和解释之间的对应关系。

| 环节 | 用户此刻做什么 | 页面提供什么 |
| --- | --- | --- |
| 提问 | 注意到一个具体问题 | 一句话和一个可辨认的对象 |
| 预测 | 形成自己的判断 | 选择、标记或简短思考的机会 |
| 演示 | 看清基本过程 | 可暂停、回放的短演示 |
| 操作 | 改变与问题有关的条件 | 一个主要操作，标明当前值 |
| 反馈 | 对照预测和结果 | 对象变化、数值或状态、原因说明 |
| 迁移 | 用同一理解处理新情况 | 一个换了材料的小问题 |

例如在筛选场景里：先问哪些卡片会留下，让用户预测，再展示一张卡片经过条件判断的过程。用户修改阈值后，所有卡片重新判断，页面解释数量为什么变化。最后换一组数据请用户判断。

预测用于帮助用户形成判断，可以允许跳过。探索过程中随时能重试，避免用户因为一次错误失去继续观察的机会。

## 六 让讲解跟着同一个对象和状态走

先写“此刻用户看到什么”，再写这一步的讲解。每段讲解尽量只指向当前画面中的一项变化。

| 当前状态 | 展示 | 讲解要点 |
| --- | --- | --- |
| 尚未操作 | 保持完整的初始对象 | 提出问题，说明可以改变哪个条件 |
| 正在操作 | 显示条件的当前值和对象变化 | 简短提示动作与结果的对应关系 |
| 结果稳定 | 保留原状态与新结果的比较 | 解释为什么发生变化 |
| 更换条件 | 重新计算或重新组织展示 | 更新解释，保留可比较的基准 |

“阈值改为 30 后，有两张卡片不再满足条件，所以结果从四张变成两张”比固定的“观察变化”更能支持理解。需要解释多个步骤时，提供逐步查看和回放。

制作时让当前条件、对象结果、统计和解释使用同一份状态。控件改变后一起更新；重置时一起回到初始状态。这样能避免文字还在解释上一步、画面已经显示下一步。

## 七 为每个操作写清用途和结果

交互在制作前至少写清五件事：用户改变什么、哪些条件固定、对象如何响应、解释如何变化、怎样重新开始。

开始时优先让用户一次改变一个主要条件，方便比较。等基本关系清楚后，再增加多个条件的组合。对于容易混淆的情况，保留并排比较、上一结果或重置入口。

检查一项交互是否值得保留，可以问：**用户完成这个动作后，多理解了什么？** 翻页和导航服务于浏览；决定概念能否被理解的操作，需要产生可观察、可解释的结果。

用户输入为空、条件不成立、结果为空或暂时无法计算时，也要给出明确反馈。这些状态有时正是理解规则的好例子。

## 八 用最小场景检验方法

先完成一个概念、一个主要操作、一个解释和一个迁移问题。先检验这些环节是否接得上，再扩充整本书或整套章节。

请一位接近目标受众的人试用，观察以下证据：

1. 他能说出这个场景在问什么。
2. 他知道可以改变什么，并能预期大致结果。
3. 他操作后能解释结果，能指出条件与变化的关系。
4. 换一组材料后，他仍能应用这个关系。

若只能复述页面文字，补一个需要作出判断的任务；若会操作但说不清原因，调整展示和解释；若看不出能动哪里，先解决操作提示。记录实际出现的问题后再修改。

## 不同主题怎样调整

对于公式、算法等规则明确的内容，用明确规则生成结果，同时标出假设和简化。对于历史和社会议题，让用户查看材料、比较解释，并保留时间、来源与不确定性。对于艺术和表达，让用户比较自己的选择如何改变作品，反馈可以描述差异和意图。

当内容依赖事实、测量或真实引文时，应在设计前核对来源。模拟中的预设、作者的解释、用户的判断应当能被区分。探索性任务允许多种合理结果，评价依据需要提前说清楚。

## 开工前的最小交付

完成[主题规划模板](templates/topic-brief.md)中的目标、内容关系、表达规则和一个场景。再按[验收清单](review-checklist.md)走查：每一个要点都有对应展示，每一项主要操作都有反馈，每一段解释都指向当下的对象和状态。走通一个场景后，再沿用同一套规则扩展。
