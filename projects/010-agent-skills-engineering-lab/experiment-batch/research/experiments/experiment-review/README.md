# 实验：审查 008 卡片收藏的备份处理

## 任务与范围

按固定上游提交 `aeac41d4d005999432bb7312f7ff06383a91d59d` 的 [code-review-and-quality](https://github.com/addyosmani/agent-skills/blob/aeac41d4d005999432bb7312f7ff06383a91d59d/skills/code-review-and-quality/SKILL.md)，只读检查实际项目 `008-ultraman-card-draw/app/app.js` 的收藏备份校验、保存和导入路径。008 的 README 声明：导入先校验、确认后替换；保存失败时原收藏不应改变。

本次不是 PR 合并审查，也不是全面安全审计。仅在 Node 的隔离 VM 执行项目源码中的三个函数，并以虚构数据和内存模拟存储；没有访问或修改真实浏览器存储、008 源码或用户收藏。

## 执行过程

1. 了解项目的导入替换和保存失败约定，检索现有关于备份的验证资料。
2. 从上游技能的正确性、可读性、架构、安全、性能五个角度阅读相关代码；重点检查用户输入和失败路径。
3. [check-backup.cjs](check-backup.cjs) 从实际 `app.js` 读取 `validCard`、`parseBackup` 和 `save` 原函数，在内存隔离环境中验证虚构备份。
4. 执行命令：

```powershell
node projects/010-agent-skills-engineering-lab/experiment-batch/research/experiments/experiment-review/check-backup.cjs
```

实际输出：

```text
PASS: valid backup, duplicate ID, invalid image, schema, quota failure, blocked storage
```

测试确认：有效备份被接受并丢弃额外字段；重复 ID、不支持的图片地址和错误版本被拒绝；模拟存储写入失败及存储被阻止时，`save` 返回失败且内存中的原卡片未替换。

## 审查结果

- **正确性：**在上述模拟输入中没有发现与所检验约定矛盾的行为。源码中导入在解析校验后询问确认，再调用 `save`（`app.js:361–369`）；确认对话框及浏览器文件流程本轮未动态执行。
- **安全：**`validCard` 校验字段类型、长度、类别和图片格式；`parseBackup` 检查版本、数量及唯一 ID，并只提取已知字段（`app.js:41–55`）。这只是对输入边界的局部检查，不能推断整个应用不存在安全问题。
- **可读性与架构：**校验、解析和保存分别是独立函数，职责可以辨认。此次未对完整文件的维护性或所有调用路径作出结论。
- **性能：**导入文件限制为 25 MB，卡片限制为 2000 条；这些是代码中的边界，并非性能实测。没有进行大文件、内存或浏览器性能测量。
- **验证覆盖：**在所检索的项目文档和文件名中未找到针对这三个函数的自动测试；这不等于证明不存在其他测试。当前试验补充了有限的函数级证据，不替代浏览器端到端测试。

## 限制和可学到的做法

采用上游五个维度有助于把“代码看起来正确”拆为输入校验、失败时状态、维护性及性能边界等问题。这个实验没有基线对照，不能量化 Skill 改善幅度；也没有做上游建议的变异测试、真实浏览器确认流程、刷新后数据验证或全面安全审计。本次没有发现需要改 008 的已证实问题，不因此宣称其余行为都正确。
