## 它的能力到底是什么

它把我们给 AI 的要求、工作方法及工具配置集中保管，并提供导入、修改、测试、分发和恢复入口。实际执行任务的仍是相应 AI 工具、模型和连接的外部服务。

| 管理对象 | 用普通话解释 | 可以复用成什么 |
| --- | --- | --- |
| 提示词 Prompt | 一段反复使用的要求，例如写作格式、审查清单；可分类、搜索、加变量、保留版本 | 填入本次主题后复制使用，或调用配置好的模型测试 |
| 技能 Skill | 工作流程，加上需要的脚本、参考资料等文件；可从商店、仓库或本地导入 | 安装到支持的 AI 工具，让工具加载并使用这套方法 |
| 规则 Rules | 长期要求与项目规范，例如 `AGENTS.md`、`CLAUDE.md` 等文件 | 放在目标工具会读取的位置，作为任务约束 |
| MCP 连接配置 | AI 工具访问外部服务所需的连接参数 | 适配并写入目标工具配置，供该工具连接服务 |
| 插件 Plugin | 可以安装的扩展包；支持市场导入、版本与来源更新 | 分发到支持的平台，按目标工具的安装机制使用 |

配套能力包括版本与差异管理、回滚、来源更新检查、AI 生成和润色、多模型比较，以及全局和项目资源管理。数据默认保存在本机，还提供同步、完整备份、独立 CLI 和自部署 Web 等入口。不同资源和平台的支持程度有差异，不能将某一入口的全部能力套用到其他入口。

## “被 AI 复用”具体怎样发生

1. **提示词：填内容，再使用。** 保存 `请为 {{读者}} 写一篇关于 {{主题}} 的文章`，下次只填写读者和主题，随后复制使用或发给已配置的模型测试。
2. **技能：把完整文件包安装到目标目录。** `Copy` 给每个工具一份独立副本；`Symlink` 让工具指向同一份技能目录，共享后续修改。完整包可以包含 `SKILL.md`、脚本和参考资料；某些环境无法建立链接时会回退为复制。安装记录与内容指纹用于识别本地修改和冲突。
3. **规则与 MCP：维护目标工具会加载的文件。** 规则作为要求由工具读取；MCP 则通过 JSON、TOML 等配置适配目标平台。保存了配置，还需要相应工具和服务能够正常工作。
4. **插件：按支持的平台安装。** 插件分发和生效方式取决于目标平台，扩展包的跨平台使用需要相应工具支持。

因此，普通笔记交给 AI 也可以复用。PromptHub 增加的便利在于组织资产、适配目录和配置、分发安装，以及持续维护和恢复这些内容。

## 对我的价值是什么

### 可以借鉴：让日常经验形成可复用的工作方法

每日笔记积累的是事实、经历、感受和资料。其中一部分会逐渐形成反复有效的方法，例如每周复盘、整理资料、写文章或检查代码的流程。

我们可以从这些记录中提炼出模板、技能和规则，交给 AI 在后续任务中使用。这是本次讨论中“从记录笔记，进一步沉淀工具”的具体含义；这里的工具可能只是一个模板，也可能是包含脚本和资料的完整技能包。

例如，我们可以把“每周复盘”整理为：

> 阅读本周提供的日记 → 提取重要事件 → 找出反复出现的问题 → 给出下周行动。

先由人整理，或另接 AI 协助提炼，再把经过使用验证的流程保存和维护起来。以后提供新的日记材料，就能重复使用这套方法，减少每次重新说明步骤的成本。

### 什么时候值得使用

- **只收藏少量提示词时：** 与现有每日笔记的分类、搜索和记录功能重叠较多，新增价值有限。
- **方法和技能越来越多时：** 版本、更新检查、差异和恢复可以降低长期维护成本。
- **同时使用多个 AI 工具时：** 同一套技能、规则和连接配置可以集中管理，减少复制文件与重复配置。

对我最有价值的借鉴是“日常记录 → 提炼有效方法 → 形成工作资产 → 交给 AI 复用”。这是一条可考虑的产品延伸方向，本次整理不代表已决定开发，也没有改变现有笔记软件或数据。

## 需要保留的理解边界

- 仓库未承诺已接通我的每日笔记：自动检索日记、自动提炼技能、执行后回写结果，都需要另外接入和验证。
- 技能安装成功之后，仍需要目标 AI 工具加载并支持相应内容；执行质量取决于流程本身、工具及模型。
- AI 生成、翻译和测试需要配置模型服务；相关请求内容会交给所配置的服务处理。普通本地整理与这些模型调用是不同操作。
- README 明确说明私密文件夹提供应用内隐藏，本地文件本身不加密。
- 在线同步与自托管备份用途不同：WebDAV/S3 用于同步；自托管 Web 的桌面自动备份上传恢复快照，恢复需显式触发。本机扫描和向本机 AI 工具分发主要由桌面端与 CLI 负责。
