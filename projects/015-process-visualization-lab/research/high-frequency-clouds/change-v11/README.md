# 固定格点红外亮温变化 · v11

本版本从相邻真实 B13 亮温资料计算 **ΔT = 当前格点亮温 − 前一帧同一格点亮温**。输入为上级 `wide-v10/frames/` 的 16 位 PNG，单位刻度 0.01 K；先转为有符号整数再相减，避免无符号溢出。没有从显示用灰阶反推温度，没有新增下载，也没有改动原始资料。

## 时间与可比性

只接受名义扫描时刻恰好相差 600 秒的两张真实图，保持相同 EPSG:4326 网格、bbox `[85,-10,165,55]` 和 2048×1664 尺寸，共 **70 对**。两份输入的实际扫描起止、数值文件 SHA-256、原始 HSD SHA-256 和来源 URL 均保存在清单中。

- 香港时间 **08:00（00:00 UTC）**：没有前十分钟输入，不可比较。
- 香港时间 **10:40（02:40 UTC）**：当前原始帧缺档，不生成图像。
- 香港时间 **10:50（02:50 UTC）**：前十分钟缺档，不可比较；不会跨过缺档拿 10:30 代替。

其余按真实相邻帧计算。600 秒指名义扫描间隔，不表示整张图在单一瞬间曝光。

## 显示映射

两帧数值均有效，且任一帧亮温低于 265 K 的格点参与“较冷区显示筛选”。这个条件是显示选择，**不是云掩膜**。B13 也包含地表信息。

- ΔT 为负：青色 `(76,220,238)`，表示该固定格点的亮温降低。
- ΔT 为正：琥珀色 `(245,177,99)`，表示该固定格点的亮温升高。
- 透明度从 |ΔT|=4 K 到 12 K 按 smoothstep 平滑增加至约 0.65（8 位最大值 166）。恰好 4 K 时透明度为 0；因此“满足≥4 K条件的像元数”和实际非透明像元数分别统计。

图层仅将实际差值映射为颜色和透明度；不提取或生造边缘，不添加噪声、粒子、光流，不做空间过滤或时间插值。RGBA 背景透明；RGB 是常规 sRGB 显示颜色，alpha 独立，不能再按 B13 灰阶反演温度。边界融合由应用显示层处理，不写入这些差值图片。

**这不是对同一个云团的跟踪，不能解释为同一云团冷却／升温，更不是风速、流向或云移动速度。** 固定格点差值可能同时包含辐射特征移入／移出、温度变化以及观测和定位因素；颜色不代表变化原因、降雨或光学厚度。

真实示例：香港时间 13:50→14:00，在 `[105,10,125,30]` 区域，62,993 个格点满足较冷区筛选及 |ΔT|≥4 K，约占该区域 24.03%；阈值提高至 5 K 后为 50,354 个（19.21%）。这证明原资料本身有可呈现的变化，不需要虚构流动。

## 文件与复现

`frames/*.png` 是 70 张派生显示图；`manifest.json` 保存逐对来源、方法、可比性和统计；`validation-report.json` 保存全量核验。未重复保存 ΔT 数值栅格，两份原 uint16 输入足以复算。

需要 Python 3.10 或更新版本、`numpy`、`Pillow`，以及完整 `wide-v10` 数值资料和清单。在本目录运行：

```powershell
python ./process_changes.py
python ./verify_changes.py
```

验证核对全部输入及输出哈希、70 对时刻、缺档、每个可见像元的筛选与符号、颜色、独立整数公式计算的透明度及统计。网页只需显示图及运行用清单；来源和方法仍应可查看。NOAA/JMA 原资料的署名要求沿用 [大范围版本说明](../wide-v10/README.md)。

从项目根目录生成应用资源包：

```powershell
python scripts/build-cloud-changes.py
```

建包脚本使用 Python 标准库，先要求完整 70 对的通过报告，再核对 72 份数值输入、真实配对、显示图哈希和尺寸；随后复制显示图到 `app/assets/events/himawari8-change-v11/`，生成 `app/data/mangkhut-cloud-changes.json`。仅修改每帧的运行用 `url`，保留来源、方法和统计，并用 `provenanceRoot` 说明研究相对路径的基准。重复执行时跳过哈希相同的资源。

精简交付包若不保留研究目录中的第二份显示图，脚本可核验并复用已有 app 图片；若两处均缺失或哈希不符则中止，不替换为模拟素材。重新生成差值图仍需要前述完整数值输入。
