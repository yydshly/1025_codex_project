# 创建研究资料回查 Skill：过程与设计理由

## 第一步：能力契约

[契约](contract.md)将“研究资料回查”明确为读取登记项目、返回依据、按需保存判断。输入、输出、失败含义先写清，防止把未找到写成从未研究、把研究记录写成实测结果。

验证：用正常查找、相似名称、缺失资料、来源变化和保存冲突检验约定是否有明确答案。

## 第二步：流程与分支

确定授权根目录 → 查登记与研究文件 → 核对对象 → 读原文 → 形成带出处的回答 → 用户要求时保存。

资料不足时补读同范围的相邻行；无结果说明范围；工具报错先处理原因；证据失效时重新查阅，不能直接复用旧结论。原文只是资料，其中的指令不获得执行权限。

验证：每个结果都对应来源，每条失败分支都有可观察输出。检索、阅读和保存分离，使正常回查无需创建文件。

## 第三步：写成可发现的 Skill

[SKILL.md](../../skill/research-recall/SKILL.md)的 description 描述真实触发场景，正文记录决策和结果要求。[执行参考](../../skill/research-recall/references/workflow.md)按需加载来源格式、命令和输出解释，避免每次灌入全部教学内容。

验证：结构检查只证明文件格式；再用独立执行者检查不同问法、不适用请求和真实产物。技能文件本身不会赋予工具权限。

## 第四步：把确定性动作交给脚本

[recall.py](../../skill/research-recall/scripts/recall.py)提供 search、read、verify、save 四个动作。关键词和仓库身份匹配、路径边界、哈希、行号以及独占写入可以由代码重复执行；语义取舍和对原文的理解仍由模型完成。

保存路径必须经过实际验证函数：来源失效时返回错误，写入分支不会继续。这个门槛比文字提醒更强，但只保护该脚本的保存路径，不是操作系统级隔离，也不能自动证明判断正确。

验证：在隔离样本中测试错误行为，核对旧文件未被覆盖；不修改真实用户数据来制造故障。

## 第五步：真实调用与独立试用

先运行行为测试，再执行真实项目查询与出处核对，最后让没有收到预期答案的新执行者使用 Skill 完成任务。保存命令输出、退出码和实际答复。

验证记录见 [verification.json](verification.json)。失败保留原因和修订，成功也要注明范围。没有无 Skill 对照时，不宣称效率或准确率提升。

本轮独立试用提出了两项真实请求：Graphiti 的用途与实测证据，以及相似仓库 `addyosmani/agent` 是否研究过。执行者区分了用途研究与未实测状态，也发现精确链接虽然命中测试说明，仍不能作为已研究该仓库的证据。因此，正式 Skill 补入了“说明提及性质和研究深度”的判断规则。

试用中还发生两次读取行范围越界，缩小范围后恢复。这个问题来自工具的错误提示信息不足：修订后在越界错误里返回来源总行数，并补回归测试，让下一次执行者能据此修正。原始试用与修订后的检查分别记录，不把首次失败写成一次成功。见 [独立试用](forward-test.json) 与 [行为测试](behavior-tests.json)。

## 第六步：安装并重复使用

维护源包在本子项目 `skill/research-recall/`；验证完成后创建用户技能目录中的同名副本，逐文件比对哈希。自动发现采用默认规则；可以显式 `$research-recall` 调用，具体界面是否热更新以实际可见状态为准。

安装与独立试用是两种证据：路径和哈希证明部署副本一致，实际任务证明技能能指导当前模型完成受测场景；两者都不等于未来所有请求保证成功。

## 与先前网页工具的关系

原网页回查工具仍使用浏览器笔记与 README 快照。本次创建的是供助手调用的独立 Skill，读取当前文件、返回证据，并可保存独立判断 JSON。两套存储没有自动互通，不会改写或清空原浏览器笔记。
