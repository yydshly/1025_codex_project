# 009 · 资料理解与检索研究

从 DeepTutor 与 NotebookLM 的资料学习场景出发，判断额外建库和维护是否值得。对照26个研究对象，拆解解析、分块、表示、检索、关系与时间的原理；用同题样例和实验协议，规划可追溯阅读、跨日回顾、经验复用、自适应复习和专题研究。

## 研究问题

1. 文档中的文字、表格、版面、来源和时间，如何转换为可供检索的内容？
2. 关键词、向量、章节树和知识图谱分别解决什么问题，又会丢失什么信息？
3. 模型、数据库、解析器、完整应用分别承担什么职责？
4. 怎样用虚构样本和可追溯证据评估结果，避免把演示当作结论？

## 当前认识

- 索引可以方便查找原始资料，并不等于训练模型。小型资料集也可能适合直接阅读或全文搜索，RAG 不是唯一选择。
- 解析、召回和生成是不同环节。资料未被正确解析或检索到，模型就可能缺少关键依据；检索到正确资料也不保证生成结论正确。
- 业务界面与展示不是知识处理本身，但业务目标会影响系统需要保留的结构、时间和引用位置。
- DeepTutor 与 NotebookLM 在资料问答、练习和内容生成方面重叠。前者是可自行部署和扩展的学习工作台；后者是 Google 托管的独立产品，不是开源库。Google 于 2026 年将 NotebookLM 更名为 Gemini Notebook。
- 不同项目处在不同层次，不能只按 Star、功能数量或技术名称比较优劣。研究对比与局限见[研究笔记](research/notes.md)。

| 教学建模 | OATutor、pyKT、pyBKT、Tutor MCP | 了解基于答题历史的技能估计与复习安排，区分模型预测和实际教学效果。 |
| 研究与评估 | STORM、OpenResearcher、Ragas | 研究多视角提问、研究轨迹训练，以及回答与来源的核验。 |

## 可扩展能力与取舍

- 论文/教材：定位表格、解释概念、返回原页，先与直接阅读比较。
- 跨日记录：找回前后原话、梳理观点与状态变化；仅用虚构记录开展测试。
- 经验复用：检索成功案例，人工审核后沉淀为知识卡、操作步骤或提示词；自动转成工具仍需额外实现。
- 学习与研究：将技能掌握估计与讲解生成分工，整理多视角、可追溯的专题材料。

网页的统一目录覆盖26个对象，均可搜索、按角色筛选、直接定位和展开原理；可选2–3项并排比较职责、机制、价值、依赖和验证任务。19项为重点研究，另7项为5种延伸工具及2种应用对照，角色不同，不作为同类强弱榜。

底层库可借鉴的核心价值是：结构与来源的保留、可替换的表示/检索方法、关系与时间表达，以及可复查的评估。我们可进一步沉淀统一来源字段、模块接口、可重建索引与可审查生成记录，为多个业务界面复用。业务中的掌握估计、选题与反馈同样需要独立设计，不能只视作展示。

## 本轮补全

- 5个算法专题：解析模式、结构分块、关键词/稠密/词元检索、融合与重排、关系与时间。每项包含过程、失败例、研究问题和官方依据；比较精确到引擎/模式/版本，不按库名固定划分算法。
- 可点击文字路线与场景选型表：说明同层替换、跨层组合和可跳过的环节；保留第三版总览原图。
- [同题虚构材料和人工答案](app/data/scenario-v1.json)：表格、同义表达、历史状态、乱序导入、对象混淆和无答案共6题；没有工具运行结果，也不是已经生成/解析的PDF。
- [实验协议](research/experiment-protocol.md)和[CSV空记录模板](app/data/experiment-record-template.csv.txt)：固定条件、改变项、验收依据，以及首次导入、增量更新、查询和维护成本分别记录。

## 后续演示规划

计划先用虚构、不含私人内容的材料，对照简单基线，分别检查文档解析、中文检索和时间关系。每次明确固定条件与改变项；完成逐题输出、来源和失败记录后再决定是否扩展。每一步只在真实运行后记录版本、模型、费用与结果。详细输入、对照方式与验收条件见[实验协议](research/experiment-protocol.md)。

**目前没有安装或运行这些上游项目，也没有下载模型、实测性能或声称取得演示结果。** 研究阶段不连接、不导入和不修改 ReflectFlow 正式库、编辑缓存或任何其他私人资料。后续实施前应明确测试环境、模型来源和数据处理方式，遵守工作区保护约定。
