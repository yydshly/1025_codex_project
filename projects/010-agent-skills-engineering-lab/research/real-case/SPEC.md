# 真实案例规格：研究回顾入口

日期：2026-10-28。范围：010 子项目中的本地演示与学习记录。本文定义应达到的行为；实际结果见 [verification.md](verification.md)。用户已要求结合近期真实需求实施并汇总网页，本轮按该授权推进，没有虚构逐阶段人工批准。

## 目标与真实依据

用户在本聊天开头询问“我们以前研究过这个库吗”，随后希望理解研究对象的功能、价值、用法和实现。总库已登记 10 个项目，研究说明分散在各自目录。目标是让用户完成：

**输入库名、仓库链接或能力词 → 找到当前总库的相关项目 → 核对来源段落 → 记录自己的理解 → 导出并恢复回顾笔记。**

选题依据：
- 总库 `AGENTS.md` 指定 `projects.json` 为登记来源。
- 009 README 提出可追溯阅读、跨日回顾与经验复用。
- 006 README 讨论将有效经验沉淀为工作资产，减少重复说明。
- 本需求直接复用真实研究材料；本轮不连接日记、私人资料或外部模型。

备选是执行 009 的关键词检索基线实验。选择当前方案，是因为它能直接服务近期研究回顾，并在有限范围内完整观察需求、实现、验证和交付的关系。

## 第一版能力与边界

| 模块 | 职责 | 输入与输出 | 依赖 |
| --- | --- | --- | --- |
| 来源快照 | 从登记项目读取研究说明，保留来源 | `projects.json` 与允许列表中的 README → 浏览器数据、来源清单 | 现有研究总库 |
| 检索核心 | 规范化查询并返回匹配项目与段落 | 查询、阶段、快照 → 确定性结果 | 来源快照 |
| 来源查看 | 展示命中原文、路径、行号和哈希 | 结果引用 → 对应快照片段 | 检索核心 |
| 回顾笔记 | 保存、导出和合并用户笔记 | 项目编号与文本 → 浏览器本地状态 | 已知项目集合 |
| 学习过程 | 解释 Skill 如何控制本次交付 | 规格、计划、实际证据 → 六步导览与覆盖表 | 全部阶段 |

本轮不增加向量检索、模型问答、用户账号、云同步或新的网络 API。未命中仅表示当前快照未找到，不能推断用户此前从未研究。注册状态“已总结”不能解释为上游软件已安装实测；`createdAt` 应称“收录日期”。

## 查询与来源契约

- 空查询显示登记项目；名称与关键词匹配不区分拉丁字母大小写。
- 多关键词采用 AND：结果需满足全部查询词。阶段筛选与查询同时生效。
- 对 GitHub 仓库链接规范化后，定位登记的来源；不访问任意输入 URL。
- 保留项目编号、名称、摘要、阶段、标签、来源与收录日期。README 段落保留文件路径和原始行号；文件 SHA256 用于核对快照。
- 索引是可重建派生产物。生成器不改写总库登记或各项目 README。
- 来源查看展示的是构建时快照；哈希一致能说明文件与该快照一致，不能证明资料内容本身正确。

## 笔记契约

浏览器本地键：`agent-skills-recall-notes-v1`。不同浏览器、用户配置或 origin 的状态彼此独立。浏览器清理可能移除本地笔记，因此提供导出入口；本轮不进行任何清理。

导出与粘贴导入的格式：

```json
{
  "schemaVersion": 1,
  "notes": [
    { "projectId": "010", "text": "我本次理解到的内容" }
  ]
}
```

- 只接受上述字段结构；拒绝未知版本、未知项目编号、同一备份中重复编号和额外字段。
- 单条文本最多 5,000 字符；导入 JSON 文本最多 100,000 字符。
- 同一项目相同文本导入应幂等；新增项目笔记可合并。
- 同一项目已有非空文本与导入的非空文本不同，应报告冲突并保留原状态。
- 导入空文本不覆盖已有非空笔记。
- 先完整验证再写入。非法输入、冲突或存储写入失败时，不显示成功，不覆盖原已保存状态。
- 笔记与搜索文本均按文字展示，不作为 HTML 或脚本执行。
- 拒绝未知版本属于输入边界；没有演练版本转换，不能标为完成迁移。

## 技术栈、结构与风格

沿用 010 的原生 HTML、CSS、JavaScript 静态页面；索引生成和行为测试使用 Node 内置能力，无需新增第三方依赖。当前运行时版本由真实验证记录填写。

- `app/real-case-data.js`：本轮教学结构及 25 项 Skill 覆盖。
- `app/recall-data.js`：生成的浏览器检索数据。
- `app/recall-core.js`：可独立测试的查询和笔记逻辑。
- `scripts/build-recall.mjs`：来源快照生成与一致性核对。
- `tests/recall.test.mjs`：行为测试。
- `research/real-case/`：规格、约束、计划、来源清单与验证证据。

遵循现有静态页面风格；核心逻辑与 DOM/存储副作用分离，函数命名表达行为。用户内容采用文本节点，避免直接拼接为 HTML。示意：

```js
output.textContent = note.text; // 用户笔记作为文字展示
```

## 可重复命令

在 010 子项目目录执行：

```powershell
node scripts/build-recall.mjs
node scripts/build-recall.mjs --check
node --test tests/recall.test.mjs
node --check app/recall-core.js
node --check app/real-case-data.js
node scripts/serve.mjs
```

现有总库结构检查在仓库根目录执行：

```powershell
npm.cmd run check
```

浏览器验收使用本轮真实服务地址；已运行的服务可复用，不需要重复启动。命令存在不代表已运行，结果与失败见验证记录。
