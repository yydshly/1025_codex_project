# 规格：虚构资料关键词查找原型（实验稿）

## 目标

研究人员从少量虚构资料中查找包含指定文字的记录，同时看到来源标识和原文；用来验证最简单的关键词查找基线，不实现语义检索或回答生成。

假设：工具运行于本地命令行；输入为 UTF-8 JSON 文件，每条记录含 `id`、`source`、`text` 字符串；字面子串匹配、大小写不敏感；最多返回三条，保持输入顺序。所有内容均为虚构材料。这些是假设，并未经过实际用户确认。

## 技术栈

拟用 Python 3 标准库，具体版本以未来实际运行环境为准；不依赖数据库、网络或第三方模型。

## 命令

以下是拟议命令，仅用于说明预期接口，不代表文件已经存在或命令已运行：

```powershell
python search.py --input sample.json --query 纸船
python -m unittest discover -s tests -v
```

## 项目结构

拟议的独立原型目录：`search.py` 为命令入口；`sample.json` 为虚构样例；`tests/test_search.py` 为标准库测试；本规格为需求依据。所有路径相对于未来原型目录，当前没有创建这些文件。

## 代码风格

数据字段使用小写名称；匹配函数只接收参数，不访问全局状态。预期风格示例（不是运行结果）：

```python
def matches(text: str, query: str) -> bool:
    return query.casefold() in text.casefold()
```

## 测试策略

使用 `unittest` 检查字面匹配、大小写、截断和输入错误；运行命令行测试核对输出包含原文与来源。准备三条以上的虚构材料，另外检查中文、无匹配和错误 JSON。任何性能结论或真实数据适用性均不在本实验范围。

## 边界

- **始终：**仅使用虚构资料；输出可追溯来源；记录测试结果。
- **按实际授权处理：**改变数据来源、引入依赖或扩展到真实日记前，先确认现有授权与保护要求。
- **禁止：**读取、修改或导入 ReflectFlow 正式库、编辑缓存及其他私人数据；把原型结果宣称为语义理解。

## 验收条件

1. 输入 `纸船`，只返回原文含该连续字符串的记录，每条显示 `id`、`source` 和 `text`。
2. 英文查询大小写不敏感：查询 `ALPHA` 可匹配 `alpha`。
3. 多于三条匹配时，按原输入顺序只返回前三条。
4. 无匹配时清晰显示“无匹配”，不编造结果。
5. 空查询、JSON 解析失败或必需字段缺失时显示错误并返回非零退出码，不输出成功结果。
