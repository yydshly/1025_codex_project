# 主题体验验收清单

[完整方法](method.md) · [主题规划模板](templates/topic-brief.md)

先检查一个完整场景，再检查章节之间是否沿用同一套表达。每项写明通过、需修改或不适用，并记录依据。

## 连续主题体验是否成立

- [ ] 入口的载体与动作能够建立主题语境。
- [ ] 有一个可辨认的对象或线索贯穿各章。
- [ ] 每一章都承接前面，并增加一个新发现。
- [ ] 材质、字体、插图与动作规则保持连贯。
- [ ] 翻页或转场保留上下文，前后返回时状态符合约定。
- [ ] 讲解、展示和操作共同推动主题继续展开。

## 一个场景是否讲清楚

| 检查项 | 怎样判断 |
| --- | --- |
| 目标具体 | 能说清用户最后应解释、判断或完成什么 |
| 内容有对应展示 | 场景中的主要概念都能指向具体对象或变化 |
| 讲解指向当前画面 | 用户能找到文字正在解释的对象与状态 |
| 主要操作有意义 | 能说明这个操作帮助理解了哪个关系 |
| 条件可辨认 | 用户知道自己改变了什么，哪些条件没有变 |
| 反馈可解释 | 结果变化时，有对应的状态、数量或原因 |
| 可以比较和重试 | 用户能恢复初始状态，或对照两次结果 |
| 新例子可检验 | 检验任务需要应用理解，而不只是重复点击 |

## 整体是否统一

- [ ] 同一概念的名称、形状和含义跨场景一致。
- [ ] 颜色、大小、位置和动作的含义有稳定约定。
- [ ] 风格与主题有关，装饰能保持主要对象清楚。
- [ ] 后一场景使用前一场景已建立的理解，再引入新关系。
- [ ] 条件、画面、统计和讲解同时更新，重置时一起恢复。
- [ ] 窄屏和键盘可完成主要操作，状态表达兼顾颜色、声音和动态效果的替代方式。
- [ ] 实际规则、模拟假设、来源材料和作者解释可以区分。

## 常见断点与修改方向

| 现象 | 优先检查和修改 |
| --- | --- |
| 看起来很统一，但说不出学到什么 | 收窄理解目标，加入换材料的检验任务 |
| 能操作，却解释不出结果 | 明确固定条件，补齐变化与原因的对应 |
| 文案与画面各说各的 | 按状态重写文案，让它指向当前对象 |
| 用户不知道能动哪里 | 显示操作提示、默认值和可用动作 |
| 操作很多，理解没有增加 | 保留服务于核心关系的操作，逐步引入新条件 |
| 示例一换就不会判断 | 检查用户是否理解规则，补一次不同材料的比较 |
| 只有完成率和停留时长 | 增加解释原因、预测新结果或独立完成的观察 |
